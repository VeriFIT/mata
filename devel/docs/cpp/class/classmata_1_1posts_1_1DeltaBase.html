Class mata::posts::DeltaBase¶

template<typename P, typename TT = DefaultTransitionTraits<P>>
class DeltaBase : public mata::posts::KeyedAccess<DeltaBase<P, DefaultTransitionTraits<P>>, P>¶

The generic transition relation: a vector of posts indexed by source state.

A vector of posts indexed by source state, over a chain of posts ending in a set of targets. The depth is deduced from P as key_arity. Posts are named by key index, not by container count: Key<0> is the topmost symbol, and PostAt<key_arity> is the innermost post.

See also

mata::posts::DefaultTransitionTraits.

See also

mata::DeltaLike.

Template Parameters:

  • P – The post reached from one source state, itself parameterised down to the targets.

  • TT – What one transition of this relation looks like and how to build one: a traits with a Type and a make(). Defaults to the symbol-named triple at arity 1 and to the tuple-keyed transition above it.

Transition-shaped members

Generic in the arity: a transition is taken apart with its type’s parts() and the pieces are forwarded to the keyed overload of the matching arity. What a transition is comes from the traits. Only Transitions, which has to carry the keys, is still arity 1.

Keys on the transitions

Which outermost keys are in use. They ask nothing of a key beyond the ordering the posts already rely on, so a relation keyed by an interval or a weight has them too; what those keys stand for is that relation’s business. Protected for the same reason: a relation re-exports the ones it wants under the names that fit its keys, with a using-declaration or a forwarder. mata::Delta does the latter, as symbols, since for the shipped relation a key is one.

The three variants indexed by the key’s value need an unsigned integer for it.

PostType &mutable_state_post(State source)¶

Get mutable (non-constant) reference to the state post of source.

The function allows modifying the state post. BEWARE, IT HAS A SIDE EFFECT. If we try to access a state post of a source which is present in the automaton as an initial/final state, yet does not have allocated space in the relation, a new state post for source will be allocated along with all state posts for all previous states. This in turn may cause that the entire post data structure is re-allocated. Iterators into the relation will get invalidated. The relation cannot see edits made through the reference, so the next query of the transition count recounts. The reference may be used for edits only until that query: num_of_transitions(), empty(), or any operation that may call them. Obtain the reference again after such a query.

Parameters:

source – Source state of a state post to access.

Returns:

State post of source.
