Detailed Description

Definition of one post of a relation, and one entry of it.

Post structure

A relation is DeltaBase indexed by source state, over a chain of posts ending in a set of targets. There is one post per key, so a relation with n keys is n posts deep:

DeltaBase -> Post -> Post -> ... -> Targets
key 0 key 1 (a state, or a state with a payload)

A Post is an ordered map from one key to the post nested under it. Iterating over one yields its PostEntry objects, each one key paired with the post beneath it. The same two classes make up every step of the chain. mata::StatePost and mata::SymbolPost are aliases for the depth-2 instantiation. PostChain spells a chain outermost key first.

Sortedness

Every post is sorted by key, and the innermost one by target. Lookups binary-search on it, and Post::first_epsilon_it() scans backwards relying on that order alone: a sorted range splits at any threshold into "below" then "at or above". A post that does not maintain the order still compiles, and silently returns wrong iterators. The order may be broken temporarily: push_back and emplace_back append without restoring it, which is faster when building from unordered input. It has to be then restored by sorting before any lookup, iteration order or comparison is relied upon. A post advertises that it maintains the invariant with sorted_by_key / sorted_by_target and exposes is_sorted().
