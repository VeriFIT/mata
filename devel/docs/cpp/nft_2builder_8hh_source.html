62/**
63 * Loads an automaton from a single parsed section of the mata format.
64 *
65 * Unlike the @c IntermediateAut overload below, this one reads @p parsec verbatim: `%Initial` and `%Final` are taken
66 * as plain lists of state names and a body line is always a `source symbol target` triple. State names are therefore
67 * arbitrary strings, not subject to the naming markers that @c IntermediateAut parses; symbol names are still
68 * resolved through @p alphabet, which decides which of them are valid. This overload is also the only one that reads
69 * the level metadata: `%Levels` assigns `state:level` pairs and `%LevelsNum` sets the number of levels, both of which
70 * the @c IntermediateAut path ignores. The two overloads consequently accept different inputs and cannot be merged
71 * without changing observable behavior.
72 *
73 * @param state_map If not @c nullptr, the map from state names to states, which all overloads and readers fill in the
74 * same way. The names it maps beforehand keep their states, each allocated (with the default level) when the input
75 * uses its name; a final formula of an @c IntermediateAut that is true or negates states uses every name of the map
76 * it does not negate. Every other name gets the lowest state that the automaton does not have yet and that no name
77 * of the map had beforehand, so that it never shares the state of a mapped name, used later or not at all.
78 */
79Nft construct(const parser::ParsedSection& parsec, Alphabet* alphabet, NameStateMap* state_map = nullptr);

111/**
112 * Reads an NFT from the `.mata` format in @p nft_in_mata with the fast reader of explicit alphabets.
113 *
114 * The reader skips @c mata::parser::parse_mf(), and reads only the inputs whose transitions are `source symbol target`
115 * triples, whose `%Initial` and `%Final` lines list states, and whose `%Levels` and `%LevelsNum` lines give each
116 * state at most one level as a decimal number without leading zeros that fits @c Level. For those, it returns the
117 * NFT @c construct() returns from @c parse_mf() of @p nft_in_mata, with the states numbered the same.
118 *
119 * @param nft_in_mata Input with a single `@NFT` or `@NFT-explicit` section.
120 * @param alphabet Alphabet translating the symbol names; @c nullptr reads them as numbers (@c IntAlphabet).
121 * @param state_map If not @c nullptr, receives the map from state names to states, see @c construct().
122 * @return The NFT, or @c std::nullopt when @p nft_in_mata needs the general reader, as do malformed inputs.
123 * @p state_map is then left unchanged, while @p alphabet may have learned symbols of the lines read before.
124 */
125std::optional<Nft> parse_explicit_from_mata(
126 std::string_view nft_in_mata, Alphabet* alphabet = nullptr, NameStateMap* state_map = nullptr
127);

179/**
180 * @brief Creates Nft from @p nfa with specified @p num_of_levels automatically.
181 *
182 * It assumes that @p nfa is a representation of an NFT without jump transitions.
183 * It assigns to each state the level based on the distance from the initial state.
184 * For example, if there are 2 levels, the initial states are level 0, the successor
185 * states are level 1, the states after that level 0, etc.
186 *
187 * If you only have one level, then it is more efficient to call the constructor that
188 * takes Nfa as input.
189 *
190 * States unreachable from the initial states get the default level 0: any level is vacuously correct for them.
191 *
192 * @throws std::runtime_error if some state should be assigned two different levels
193 * or if the final state is not at level 0.
194 */
195Nft from_nfa_with_levels_advancing(nfa::Nfa nfa, size_t num_of_levels);
