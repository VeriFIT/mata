57/**
58 * Creates Tabakov-Vardi random NFA.
59 * The implementation is based on the paper "Experimental Evaluation of Classical Automata Constructions" by Tabakov and
60 * Vardi.
61 *
62 * @param num_of_states Number of states in the automaton.
63 * @param alphabet_size Size of the alphabet.
64 * @param states_transitions_ratio_per_symbol Ratio between number of transitions and number of states for each symbol.
65 * The value must be in range [0, num_of_states]. A value of 1 means that there will be num_of_states transitions for
66 * each symbol. A value of num_of_states means that there will be a transition between every pair of states for each
67 * symbol.
68 * @param final_state_density Density of final states in the automaton. The value must be in range [0, 1]. The state 0
69 * is always final. If the density is 1, every state will be final.
70 * @param seed Seed for the PRNG used. If no seed is given, the algorithm chooses one uniformly at random.
71 */

80/**
81 * Loads an automaton from a single parsed section of the mata format.
82 *
83 * Unlike the @c IntermediateAut overload below, this one reads @p parsec verbatim: `%Initial` and `%Final` are taken
84 * as plain lists of state names and a body line is always a `source symbol target` triple. State names are therefore
85 * arbitrary strings, not subject to the `q`/`a`/`n` naming markers or to the Boolean formulas that
86 * @c IntermediateAut parses; symbol names are still resolved through @p alphabet, which decides which of them are
87 * valid. The two overloads consequently accept different inputs and cannot be merged: routing this one through
88 * @c IntermediateAut would subject the state names to the naming mode of the section (with the default `%States`
89 * marked naming rejecting every name not starting with `q`) and would renumber states, as the @c IntermediateAut
90 * path collects names from an unordered set.
91 *
92 * @param state_map If not @c nullptr, the map from state names to states, which all overloads and readers fill in the
93 * same way. The names it maps beforehand keep their states, each allocated when the input uses its name; a final
94 * formula of an @c IntermediateAut that is true or negates states uses every name of the map it does not negate.
95 * Every other name gets the lowest state that the automaton does not have yet and that no name of the map had
96 * beforehand, so that it never shares the state of a mapped name, used later or not at all.
97 */
98Nfa construct(const mata::parser::ParsedSection& parsec, Alphabet* alphabet, NameStateMap* state_map = nullptr);

114/**
115 * Reads an NFA from the `.mata` format in @p nfa_in_mata with the fast reader of explicit alphabets.
116 *
117 * The reader skips the intermediate representations of the general reader (@c mata::parser::parse_mf() and
118 * @c IntermediateAut), and reads only the inputs whose transitions are `source symbol target` triples and whose
119 * `%Initial` and `%Final` lines list states. For those, it returns the NFA @c parse_from_mata() has always returned,
120 * except that the initial states are numbered in the order of the input.
121 *
122 * @param nfa_in_mata Input with a single `@NFA` or `@NFA-explicit` section.
123 * @param alphabet Alphabet translating the symbol names; @c nullptr reads them as numbers (@c IntAlphabet).
124 * @param state_map If not @c nullptr, receives the map from state names to states, see @c construct().
125 * @param keep_quotes Whether quoted names of body lines keep their quotes, see @c mata::parser::parse_mf().
126 * @return The NFA, or @c std::nullopt when @p nfa_in_mata needs the general reader, as do Boolean formulas, bitvector
127 * alphabets, enumerated namings, and malformed inputs. @p state_map is then left unchanged, while @p alphabet may have
128 * learned symbols of the lines read before.
129 */
130std::optional<Nfa> parse_explicit_from_mata(
131 std::string_view nfa_in_mata,
132 Alphabet* alphabet = nullptr,
133 NameStateMap* state_map = nullptr,
134 bool keep_quotes = false
135);

137/**
138 * Reads NFAs with bitvector alphabets (`@NFA-bits`) over one shared set of minterms, as the general reader followed by
139 * @c Mintermization::mintermize() of all of them together does, but without the intermediate representations.
140 *
141 * Transitions whose formulas are the usual Boolean combinations of symbols are read directly into BDDs. Any other
142 * `@NFA-bits` input goes through the general reader inside @c add(), so that all added automata still share one
143 * partition. The NFAs are the ones @c parse_from_mata() has always returned, except that the initial and the listed
144 * final states are numbered in the order of the input.
145 */
146class BitvectorNfaReader {
147 public:
148 BitvectorNfaReader();
149 BitvectorNfaReader(BitvectorNfaReader&&) noexcept;
150 BitvectorNfaReader& operator=(BitvectorNfaReader&&) noexcept;
151 ~BitvectorNfaReader();
152
153 /// How @c add() took an input.
154 enum class Read : std::uint8_t {
155 /// Not a single NFA section with a bitvector alphabet; nothing of it is kept.
156 Rejected,
157 /// Read directly into BDDs.
158 Directly,
159 /// Read by the general reader, as the formulas leave the shapes read directly.
160 ByGeneralReader,
161 };

229/**
230 * @brief Create NFA from @p regex
231 *
232 * The created NFA does not contain epsilons and is trimmed; with @p reduce, it is also reduced by simulation reduction.
233 * It uses the parser from RE2, see mata/parser/re2praser.hh for more
234 * details and options.
235 *
236 * At https://github.com/google/re2/wiki/Syntax, you can find the syntax
237 * of @p regex with following further limitations:
238 * 1) The allowed characters are the first 256 characters of Unicode,
239 * i.e., Latin1 encoding (ASCII + 128 more characters). For the
240 * full Unicode, check mata/parser/re2praser.hh.
241 * 2) The created automaton represents the language of the regex and
242 * is not expected to be used in regex matching. Therefore, stuff
243 * like ^, $, \b, etc. are ignored in the regex. For example, the
244 * regular expressions a*b and ^a*b will both result in the same
245 * NFA accepting the language of multiple 'a's followed by one 'b'.
246 * See also issue #494.
247 *
248 * @sa mata::parser::create_nfa()
249 *
250 * @param regex regular expression
251 * @param reduce whether to reduce the NFA using simulation reduction; costly for large regexes
252 *
253 * @throw std::invalid_argument on a regex RE2 cannot parse or cannot compile within its program memory budget.
254 * @throw std::runtime_error on a regex program containing an instruction the converter does not support.
255 */
256Nfa create_from_regex(const std::string& regex, bool reduce = true);
