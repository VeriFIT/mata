8/// @c MATA_HAS_GENERATOR_SUPPORT (from the generated @c mata/config.hh) is 1 when @c std::generator (C++23
9/// `<generator>`, P2502) was available to the standard library libmata was built with, 0 otherwise. Some standard
10/// libraries -- notably Apple's system libc++ shipped with Xcode on macOS -- do not implement it at all, regardless
11/// of `-std=c++23`, so code that depends on it must be guarded by this macro instead of assuming C++23 support
12/// implies it. The value is pinned at build time because the layout of the exported @c mata::utils::LazyGenerator
13/// depends on it; a consumer whose standard library disagrees is rejected here instead of silently compiling a
14/// different layout.

16 #error "libmata was built with std::generator support, but this standard library has no std::generator"
