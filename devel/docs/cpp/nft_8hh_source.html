13/**
14 * @page nft Nondeterministic Finite Transducers (NFTs)
15 *
16 * @warning Mata provides an experimental (unstable) support for (non-)deterministic finite transducers (NFTs).
17 * The provided interface may change.
18 *
19 * @section nft_design The design of NFTs in Mata
20 *
21 * The classical transducers from textbook definitions (where a transition is a tuple of
22 * `(initial state, input symbol, final state, output string)`) are encoded using a simpler data structure for the
23 * transition relation, @c mata::nft::Delta The data structures can directly represent only transitions of the form
24 * `p -a-> s` where `a` is a single symbol or epsilon. A “high-level” transitions of the form `p -abc/def-> q` where
25 * 'abc' is an input word and def is an output word are encoded as a sequence of these 'low level' transitions:
26 * `p -a- p’ -d-> q -b-> q' -e-> r -c-> r' -f-> s` (odd transitions read letters of the input track, even transitions
27 * read letters of the output track, a transition can have epsilon instead of a letter). The primed states are a sort
28 * of internal states, to where the automaton gets after reading a letter on the input tape (in Mata called level).
29 * States are distinguished by their “level”. “Normal” states p,q,r,s have level 0, the internal states p’,q’,r’ have
30 * in this case the levels 1 (and you could have n-tape transducers where level can be larger than 1). In Mata, the @c
31 * mata::nft::Delta interface is used only for the manual handling of the internal delta representation, taking only
32 * (initial state, input symbol, final state) We find it useful to think about NFTs in Mata as normal NFAs with a single
33 * symbol on a transition (because Mata uses the same underlying data structure for NFTs as for NFAs) where states are
34 * annotated with levels. The 'NFT' states are the states with levels 0, the other levels are for the internal states.
35 * Each NFT transition is a sequence of NFA transitions, one per tape, between two states with levels 0. Each NFA
36 * transition performs a single symbol read on the tape of the source state. A sequence of symbols on transitions is not
37 * a single word on any tape, but an interleaved description of a single NFT transition over multiple tapes, e.g.,
38 * q1(l:0)-{a}->q2(l:1)-{b}->q3(l:2)-{c}->q4(l:0) (where (l:X) describes the level of the state) is a single 'NFT'
39 * transition (from a state with level 0 to another state with level 0) where the NFT symbol read is a 3-tape symbol
40 * ('a', 'b', 'c'), interpreted as 'read 'a' on tape 0, read 'b' on tape 1, and read 'c' on tape 2.' When you want to
41 * read 'af' on a single tape, you need to construct two such transitions where on the remaining tapes, you read an
42 * epsilon symbol.
43 *
44 * @section nft_usage Working with NFTs
45 *
46 * There are some utility functions to simplify creating this NFA-like Delta data structure for NFTs such as
47 * @c mata::nft::Nft::insert_word() (inserting the NFA-like sequence of transitions on different tapes: 'abcd' which
48 * means to read 'ac' on tape 0 and 'bd' on tape 1), and @c mata::nft::Nft::insert_word_by_levels() (inserting word for
49 * each tape separately: {'ac', 'bd'} to achieve the same as in the previous). If you however want precise control over
50 * the created transitions, you can omit using the utility NFT functions and build your NFT like an NFA using the
51 * Nft::Delta::* operations directly, adding a single symbol on a single tape per add() call. You will have to correctly
52 * specify the levels for the states. When working with 2-tape NFTs modelling a replace operation, we use @c
53 * mata::applications::strings::replace namespace with utility functions such as
54 * @c mata::applications::strings::replace::replace_reluctant_regex() (accepting parameters: regex as the input for the
55 * tape 0, and a word as a replacement on tape 1), etc. The notion of jumps (in the jump mode RepeatSymbol, a mode
56 * designed for NFTs) is just an optimization to reduce the size of the NFT. It is an approach to simplify the data
57 * structure for NFTs where you can say that you jump over several internal states and NFA-like transitions to up to the
58 * next state with level 0, each transition in the sequence reading the same single symbol of the jump. That is useful
59 * when, for example, having a NFT reading string 'abc' on all tapes. You can encode it as a sequence of jumps between
60 * states with level 0 as q0(l:0)-{a}->q1(l:0)-{b}->q2(l:0)-{c}->q3(l:0). Notice that the internal states are not
61 * present, but they are implied by the jump. Ideally, one should not even have to think about the levels and the
62 * intermediate states when properly using the utility functions (from the @c mata::nft::Nft class and the @c mata::nft
63 * namespace in general).
64 *
65 *
66 * @section nft_word Representing words in NFTs
67 *
68 * When working with NFTs, words on multiple levels need to be represented.
69 * We consider an NFT word with @c n levels as a vector of words of type @c mata::Word, where the word at index @c i
70 * in the vector represents the word on the level @c i.
71 * Operations on NFT words either work on each level separately (named with `_by_levels` suffix) or on the interleaved
72 * representation of the NFT word.
73 * E.g., the NFT word representing reading 'abc' on level 0 and 'def' on level 1 can be represented as either
74 * `std::vector<Word>{ Word{ 'a', 'b', 'c }, Word{ 'd', 'e', 'f' } }` (using the `_by_levels` variant) or as a word
75 * `Word{ 'a', 'd', 'b', 'e', 'c', 'f' }` (using the interleaved representation).
76 * Words may contain @c DONT_CARE (representing wildcards on the respective level, but not @c EPSILON) and @c EPSILON
77 * (representing reading an empty string on the respective level ).
78 *
79 * @see `examples/nft.cc` for a worked example.
80 *
81 * @note If you find some expected NFT operation or utility function missing, do not hesitate to let us know and we will
82 * implement it. The interface for NFTs is not stable yet, so we are open to any and all feedback.
83 */

506 /**
507 * @brief Add a new transition from @p source to @p target labeled by the symbol named @p symbol_name.
508 *
509 * Convenience wrapper mirroring @c nfa::Nfa::add_transition(), translating @p symbol_name to a @c Symbol via the
510 * resolved alphabet instead of requiring the caller to translate it themselves.
511 *
512 * Unlike the plain-@c Symbol overloads above, @p symbol_name is translated separately for each level the
513 * transition spans (i.e., @c levels[source], @c levels[next_level_after(levels[source])], ..., up to but
514 * excluding @c levels[target]), each via the alphabet resolved for that level (see @c resolve_alphabet):
515 * @p alphabet, when non-null, takes precedence over @c this->alphabets (used in @c AlphabetLevels::Mode
516 * ::MultiLevel via the level being translated for; ignored in @c Global mode) over @c this->alphabet.
517 *
518 * If every affected level translates @p symbol_name to the same @c Symbol, a single jump transition from
519 * @p source directly to @p target is added (no new states). Otherwise, since a single jump transition cannot
520 * carry a different symbol per level, the jump is unwound into a sequence of ordinary, single-level
521 * transitions, each carrying its own level's translation of @p symbol_name, through freshly created inner
522 * states.
523 *
524 * @param[in] source Source state of the new transition. Must already exist.
525 * @param[in] symbol_name Name of the symbol labeling the new transition, translated separately for each level
526 * the transition spans.
527 * @param[in] target Target state of the new transition. Must already exist.
528 * @param[in] alphabet Alphabet to translate @p symbol_name with on every affected level, taking precedence over

1530 /**
1531 * @brief Lazily enumerate the words in the language of the automaton whose length is <= @p max_length.
1532 *
1533 * Equivalent to @ref get_words(), but yields each word as soon as it is found instead of computing the whole set
1534 * up front. Prefer this over @ref get_words() when the caller may stop after finding the first few words, or when
1535 * the language might be large or infinite (with @p max_length left at its default, @ref get_words() will never
1536 * return for a cyclic automaton with an infinite language, whereas this can still be iterated and stopped at
1537 * will).

1539 * via more than one accepting path), so a duplicate is silently skipped rather than re-yielded.
1540 *
1541 * Words are yielded in shortlex order: by increasing length, and words of the same length lexicographically.
1542 * Each length is searched in its own depth-first pass, which keeps only the current descent in memory and skips
1543 * the branches that cannot reach an accepted word of that length. Every word of an infinite language is thus
1544 * eventually yielded, and the generator finishes once no longer accepted word is possible, also for a finite
1545 * language with the default unbounded @p max_length. Searching each length anew repeats the shorter prefixes.
