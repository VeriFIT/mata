18/**
19 * @brief Options of the conversion of a regex to an NFA and of the post-processing of the result.
20 *
21 * The defaults reproduce the behaviour of the overloads taking the individual parameters: epsilon transitions removed,
22 * the result trimmed and reduced by simulation reduction.
23 */
24struct Re2Options {
25 /// Translate every instruction of the regex program to a state, with an @c epsilon transition for each step that
26 /// consumes no symbol. Otherwise, the regex is converted directly to an NFA without epsilon transitions.
27 bool keep_epsilon{false};
28 Symbol epsilon{306}; ///< Symbol representing epsilon transitions.
29 Encoding encoding{Encoding::Latin1}; ///< Encoding of the regex.
30 /// Trim the created NFA. Without epsilon transitions, the conversion only creates states reachable from the initial
31 /// state, and only a branch that can never match, such as '[^\x00-\xff]' in Latin1, leaves useless states behind.
32 bool trim{true};
33 /// Reduce the created NFA by simulation reduction. The reduction costs seconds on regexes with a few thousand
34 /// states, where the conversion itself takes milliseconds; turn it off for large regexes and when the result is
35 /// determinized anyway.
36 bool reduce{true};
37 /// Approximate RE2 program memory budget in bytes. Positive values override RE2's default budget; non-positive
38 /// values preserve it. This applies to regex compilation, not to trimming or reduction.
39 std::int64_t max_mem{0};
40};

42/**
43 * @brief Creates NFA from regular expression using RE2 parser
44 *
45 * At https://github.com/google/re2/wiki/Syntax, you can find the syntax
46 * of regular expressions with following futher limitations:
47 * 1) If you use UTF8 encoding, the created NFA will have the values of
48 * bytes instead of full symbols. For example, the character Ā whose
49 * Unicode code point is U+0100 and is represented in UTF8 as two
50 * bytes c4 80 will have two transitions, one with c4 followed with
51 * by 80, to encode it.
52 * 2) The created automaton represents the language of the regex and
53 * is not expected to be used in regex matching. Therefore, stuff
54 * like ^, $, \b, etc. are ignored in the regex.
55 * 3) Only the post-processing steps requested by @p options are run on the created automaton.
56 *
57 * @sa mata::nfa::builder::create_from_regex()
58 *
59 * @param pattern regex as a string
60 * @param options conversion and post-processing options
61 * @return Nfa corresponding to pattern
62 * @throw std::invalid_argument on a regex RE2 cannot parse.
63 * @throw std::invalid_argument on a regex RE2 cannot compile within its program memory budget.
64 * @throw std::runtime_error on a regex program containing an instruction the converter does not support.
65 */
66nfa::Nfa create_nfa(const std::string& pattern, const Re2Options& options);
