13/**
14 * @page nfa Nondeterministic Finite Automata (NFAs)
15 *
16 * @section nfa_design The design of NFAs in Mata
17 *
18 * NFAs in Mata are represented using the @c mata::nfa::Nfa class. The transition relation is represented using
19 * the @c mata::nfa::Delta class, which provides an efficient way to store and manipulate transitions.
20 * The states of the NFA are represented as integers, starting from 0 up to the number of states minus one.
21 * The initial and final states are represented using the @c mata::utils::SparseSet class, which allows for efficient
22 * storage and manipulation of sets of states.
23 *
24 * @c mata::nfa::Delta is a key component of the NFA representation. It stores transitions as a
25 * *chain of posts*: a vector indexed by source state, then one ordered map per key, ending in the
26 * set of targets that key path leads to. An NFA has one key — the symbol — so its chain is
27 *
28 * 1. @c mata::nfa::Delta, a vector indexed by source state, each entry a @c mata::nfa::StatePost;
29 * 2. @c mata::nfa::StatePost, an ordered map from a symbol to the targets under it, iterated as
30 * @c mata::nfa::SymbolPost entries;
31 * 3. @c mata::nfa::StateSet, the ordered set of target states reachable over that symbol.
32 *
33 * The number of *keys* between a source state and a target is @c mata::nfa::Delta::key_arity, and
34 * it is one for every NFA and NFT in the library. It is not fixed at one by the data structure:
35 * the relation is templated on its post chain, so one may key transitions by more than one thing (a
36 * two-tape relation, say) and the chain simply has one more post in it. Counting *posts* instead
37 * makes the depth depend on where you start counting and collides with an NFT's tape
38 * @c mata::Level, which is unrelated. Count keys.
39 * @see @ref arity in @c mata/core/delta.hh.
40 *
41 * The symbol *type* is fixed: @c mata::Alphabet's virtual interface is stated in @c mata::Symbol,
42 * so a relation keyed by anything else needs its own alphabet class, declaring its own @c Symbol,
43 * and cannot use the operations here that take an @c Alphabet.
44 *
45 * The main idea behind @c mata::nfa::Nfa is that the members (@c mata::nfa::Nfa::delta, @c mata::nfa::Nfa::initial,
46 * @c mata::nfa::Nfa::alphabet, ...) do not depend on each other.
47 * This allows for some well-optimized implementations as well as easy replacement of individual members, or extensions
48 * to the NFA structure (e.g., adding levels for NFT), if needed.
49 * However, this also poses a risk of inconsistency between the members (e.g., having initial states that do not exist
50 * in the delta).
51 * The high-level functions in @c mata::nfa namespace and @c mata::nfa::Nfa class are designed to maintain the
52 * consistency of the NFA structure, but the individual members can be modified directly by the user, which may lead
53 * to inconsistencies, yet there are often useful when implementing highly-optimized algorithms.
54 *
55 * The main operation on NFAs is BFS/DFS through @c mata::nfa::Delta structure, which is used in most algorithms.
56 * The data structure is designed such that direct access to a specific transition is less efficient, but iterating
57 * through all transitions from a given source state, for all source states is efficient (e.g.,
58 * @c mata::utils::SynchronizedIterator).
59 * When designing algorithms for Mata, be sure utilize iteration through @c mata::nfa::Delta structure as much as
60 * possible.
61 *
62 * @section nfa_usage Working with NFAs
63 *
64 * The library provides various functions to create, manipulate, and analyze NFAs.
65 * The core operations on NFAs, such as union, intersection, complement, determinization, and minimization, are
66 * implemented in @c mata::nfa namespace and as methods of the @c mata::nfa::Nfa class.
67 * More advanced algorithms and utilities are available in the @c mata::nfa::algorithms and @c mata::nfa::plumbing
68 * namespaces.
69 * Users can create NFAs manually by adding states and transitions using the methods provided in the @c mata::nfa::Nfa
70 * and @c mata::nfa::Delta classes, or they can use higher-level functions to construct NFAs from regular expressions,
71 * words, or other NFAs using the functions in the @c mata::nfa::builder and @c mata::parser namespaces.
72 *
73 * @note The algorithms provided in Mata for NFAs are designed to perform only the core operations on NFAs, such as
74 * union, intersection, complement, determinization, minimization, etc., but do not by default optimize the NFAs
75 * during these operations. Users can apply optimization algorithms separately after performing the core operations,
76 * such as using the @c mata::nfa::reduce() function to reduce the resulting NFA, @c mata::nfa::minimize() to minimize
77 * the resulting NFA, or @c mata::nfa::trim() to remove unreachable and non-terminating states.
78 */

545 /**
546 * @brief Prints the language of the automaton as a regular expression
547 *
548 * The automaton is converted by state elimination, see src/nfa/regex-writer.cc. @p mode chooses what the
549 * conversion optimizes for:
550 * - @c RegexPrintMode::Fast converts as fast as possible, for a regex read by a program.
551 * - @c RegexPrintMode::Readable looks for a short, legible regex, for a regex read by a human: it converts
552 * several automata of the same language (the reduced one, the minimal deterministic one, and the minimal one
553 * deterministic backwards) in several elimination orders, simplifies the regexes algebraically, and prints
554 * the shortest one, which is never longer than the regex of @c RegexPrintMode::Fast. Running these additional
555 * conversions takes considerably longer than @c RegexPrintMode::Fast.
556 *
557 * The length of the regex is exponential in the number of states in the worst case, in both modes.
558 *
559 * The regex is written in the syntax mata::nfa::builder::create_from_regex() reads (RE2), restricted to
560 * characters, escapes ('\\n', '\\x41', '\\x{17F}'), character classes ('[a-c]'), groups, '|', '*', '+', '?',
561 * and counted repetitions ('{2}', '{2,}', '{2,5}'). The empty word alone is '()', and the empty language is the
562 * empty character class '[^\\s\\S]'.
563 *
564 * A symbol is the Unicode scalar value of its value, so it has to be at most 0x10FFFF and must not be in the
565 * surrogate range 0xD800 to 0xDFFF. With symbols up to 0xFF, reading the regex back gives the same language; with
566 * larger ones, reading it back with @c Encoding::Utf8 gives the language encoded in UTF-8. With an alphabet,
