Nondeterministic Finite automata¶

An mata::nfa::Nfa holds the transition relation delta together with the initial and final state sets (both mata::utils::SparseSet over states), all three inherited from mata::Automaton, plus an optional shared alphabet. All of them appear among the members below. mata::nfa::Delta itself is documented in Core.

page Nondeterministic Finite Automata (NFAs)

The design of NFAs in Mata¶

NFAs in Mata are represented using the mata::nfa::Nfa class. The transition relation is represented using the mata::nfa::Delta class, which provides an efficient way to store and manipulate transitions. The states of the NFA are represented as integers, starting from 0 up to the number of states minus one. The initial and final states are represented using the mata::utils::SparseSet class, which allows for efficient storage and manipulation of sets of states.

mata::nfa::Delta is a key component of the NFA representation. It stores transitions as a chain of posts: a vector indexed by source state, then one ordered map per key, ending in the set of targets that key path leads to. An NFA has one key — the symbol — so its chain is

  1. mata::nfa::Delta, a vector indexed by source state, each entry a mata::nfa::StatePost;

  2. mata::nfa::StatePost, an ordered map from a symbol to the targets under it, iterated as mata::nfa::SymbolPost entries;

  3. mata::nfa::StateSet, the ordered set of target states reachable over that symbol.

The number of keys between a source state and a target is mata::nfa::Delta::key_arity, and it is one for every NFA and NFT in the library. It is not fixed at one by the data structure: the relation is templated on its post chain, so one may key transitions by more than one thing (a two-tape relation, say) and the chain simply has one more post in it. Counting posts instead makes the depth depend on where you start counting and collides with an NFT’s tape mata::Level, which is unrelated. Count keys.

See also

arity in mata/core/delta.hh.

The symbol type is fixed: mata::Alphabet's virtual interface is stated in mata::Symbol, so a relation keyed by anything else needs its own alphabet class, declaring its own Symbol, and cannot use the operations here that take an Alphabet.

The main idea behind mata::nfa::Nfa is that the members (mata::nfa::Nfa::delta, mata::nfa::Nfa::initial, mata::nfa::Nfa::alphabet, …) do not depend on each other. This allows for some well-optimized implementations as well as easy replacement of individual members, or extensions to the NFA structure (e.g., adding levels for NFT), if needed. However, this also poses a risk of inconsistency between the members (e.g., having initial states that do not exist in the delta). The high-level functions in mata::nfa namespace and mata::nfa::Nfa class are designed to maintain the consistency of the NFA structure, but the individual members can be modified directly by the user, which may lead to inconsistencies, yet there are often useful when implementing highly-optimized algorithms.

The main operation on NFAs is BFS/DFS through mata::nfa::Delta structure, which is used in most algorithms. The data structure is designed such that direct access to a specific transition is less efficient, but iterating through all transitions from a given source state, for all source states is efficient (e.g., mata::utils::SynchronizedIterator). When designing algorithms for Mata, be sure utilize iteration through mata::nfa::Delta structure as much as possible.

Working with NFAs¶

The library provides various functions to create, manipulate, and analyze NFAs. The core operations on NFAs, such as union, intersection, complement, determinization, and minimization, are implemented in mata::nfa namespace and as methods of the mata::nfa::Nfa class. More advanced algorithms and utilities are available in the mata::nfa::algorithms and mata::nfa::plumbing namespaces. Users can create NFAs manually by adding states and transitions using the methods provided in the mata::nfa::Nfa and mata::nfa::Delta classes, or they can use higher-level functions to construct NFAs from regular expressions, words, or other NFAs using the functions in the mata::nfa::builder and mata::parser namespaces.

Note

The algorithms provided in Mata for NFAs are designed to perform only the core operations on NFAs, such as union, intersection, complement, determinization, minimization, etc., but do not by default optimize the NFAs during these operations. Users can apply optimization algorithms separately after performing the core operations, such as using the mata::nfa::reduce() function to reduce the resulting NFA, mata::nfa::minimize() to minimize the resulting NFA, or mata::nfa::trim() to remove unreachable and non-terminating states.

std::string print_to_regex(RegexPrintMode mode = RegexPrintMode::Fast, const Alphabet *alphabet = nullptr) const

Prints the language of the automaton as a regular expression.

The automaton is converted by state elimination, see src/nfa/regex-writer.cc. mode chooses what the conversion optimizes for:

  • RegexPrintMode::Fast converts as fast as possible, for a regex read by a program.

  • RegexPrintMode::Readable looks for a short, legible regex, for a regex read by a human: it converts several automata of the same language (the reduced one, the minimal deterministic one, and the minimal one deterministic backwards) in several elimination orders, simplifies the regexes algebraically, and prints the shortest one, which is never longer than the regex of RegexPrintMode::Fast. Running these additional conversions takes considerably longer than RegexPrintMode::Fast.

The length of the regex is exponential in the number of states in the worst case, in both modes.

The regex is written in the syntax mata::nfa::builder::create_from_regex() reads (RE2), restricted to characters, escapes (‘\n’, ‘\x41’, ‘\x{17F}’), character classes (‘[a-c]’), groups, ‘|’, ‘*’, ‘+’, ‘?’, and counted repetitions (‘{2}’, ‘{2,}’, ‘{2,5}’). The empty word alone is ‘()’, and the empty language is the empty character class ‘[^\s\S]’.

A symbol is the Unicode scalar value of its value, so it has to be at most 0x10FFFF and must not be in the surrogate range 0xD800 to 0xDFFF. With symbols up to 0xFF, reading the regex back gives the same language; with larger ones, reading it back with Encoding::Utf8 gives the language encoded in UTF-8. With an alphabet, a symbol is the character its name consists of instead. EPSILON is the empty word.

Parameters:

  • mode – [in] What to optimize the conversion for.

  • alphabet – [in] If specified, translates the symbols to their symbol names in the alphabet. Otherwise, the alphabet of the automaton is used, if it has one.

Throws:

std::invalid_argument – If a symbol is larger than 0x10FFFF or a surrogate, or its name in the alphabet is not a single character encoded in UTF-8.

Returns:

The regular expression.

Loads an automaton from a single parsed section of the mata format.

Unlike the IntermediateAut overload below, this one reads parsec verbatim: Initial and Final are taken as plain lists of state names and a body line is always a source symbol target triple. The two overloads consequently accept different inputs and cannot be merged: routing this one through IntermediateAut would subject the state names to the naming mode of the section (with the default States marked naming rejecting every name not starting with q) and would renumber states, as the IntermediateAut path collects names from an unordered set.

Classes of states that have the same finality, the same level, and, over every symbol, successors in the same classes.

Starts from the identity and merges states with identical successors, then states whose successors became identical by the merge, until nothing merges. inline uint64_t macrostate_signature(const StateSet &macrostate)

Signature of a macrostate: the OR of 1 << (q % 64) over its states q.

A superset can only have more bits set, so a bit present in macrostate_signature(a) and absent from macrostate_signature(b) exhibits a state of a that is missing from b and proves a ⊄ b. The converse does not hold: states that are congruent modulo 64 share a bit, so equal signatures prove nothing. The filter therefore only ever rejects, which is what the antichain subsumption tests need to stay sound.

Reduce NFA to an automaton with the minimum number of states using an external SAT solver.

Experimental. A counterexample-guided search: for k = 1, 2, …, a SAT solver looks for an automaton with k states consistent with a set of sample words, the candidate is checked for equivalence with nfa, and a distinguishing word is added to the samples until the candidate is equivalent or no k-state automaton exists. The search is exponential in the worst case and is practical only for languages whose minimal automata have about ten states.

By default, an EPSILON transition is treated as a transition over an ordinary letter, as in the other reduction algorithms. Set epsilon to “empty” to run remove_epsilon() on the input first instead. The result uses the symbols and the alphabet of nfa.

Same as Nfa::get_words_lazy(), but as a free function returning a heap-allocated wrapper instead of a std::generator.

Exists for callers that cannot drive a C++23 coroutine directly — namely the Python bindings, generated by Cython, which has no notion of C++23 coroutines/sentinels. Prefer Nfa::get_words_lazy() everywhere else.

Throws std::runtime_error when MATA_HAS_GENERATOR_SUPPORT is unset (i.e. the standard library does not implement std::generator — some, like Apple’s system libc++, do not, even under -std=c++23).

Parameters:

  • aut – Automaton whose language is enumerated.

  • max_length – Maximum length of words to be returned. Default: “no limit”; will keep yielding forever if the language is infinite.

Returns:

A heap-allocated generator; the caller takes ownership and must delete it.
