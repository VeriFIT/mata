template<class Vector>
inline void sort_and_rmdupl(Vector &vec)

Sorts vec and removes its duplicate elements.

std::sort stays the sorting algorithm: it is the fastest of the ones measured on the mixed sizes mata produces, and a specialized sort would have to be restricted to unsigned integral keys anyway, because SymbolPost compares by symbol only and would lose targets under a comparison sort. Already-sorted input is common (ordered construction, conversion from an ordered container), and the linear std::is_sorted check that detects it costs far less than the sort it avoids.

template<class Key, std::size_t InlineCapacity = std::max<std::size_t>(1, sizeof(std::uintptr_t) / sizeof(Key))>
class SmallOrdVector
#include <small-ord-vector.hh>

A set of keys kept as a sorted, duplicate-free contiguous array, like OrdVector, that stores up to InlineCapacity keys inside the object and allocates only for larger sets.

The object is a pointer-sized buffer plus a 32-bit size word: the buffer holds either the inline keys or a pointer to a heap block, which keeps its capacity in a header in front of the keys. A set lives inline until it outgrows InlineCapacity or a larger capacity is reserved. Like std::vector, it then keeps its heap block when it shrinks, while copies are made in their final form: inline when they fit, otherwise with exact capacity. On 64-bit targets the object ends with four bytes of tail padding, so a [[no_unique_address]] member followed by a 32-bit field packs both into 16 bytes.

Iterators are plain pointers; any operation that grows the set may invalidate them.

template<typename T, bool TrackInverted = true, size_t MaxMatrixBytes = 200'000'000>
class TwoDimensionalMap
#include <two-dimensional-map.hh>

A two-dimensional map that can be used to store pairs of values and their associated value.

This class can handle both small and large maps efficiently.

Values are stored in a matrix of Cell cells (4 Bytes each, unless T is smaller). The matrix rows are allocated lazily: a row is allocated and zeroed when the first value is inserted into it, so the memory footprint is proportional to the number of first-dimension keys actually used, not to the size of the first dimension. A cell holds the stored value incremented by one; zero means that no value is stored.

The largest matrix we are brave enough to allocate is MaxMatrixBytes Bytes, 200 MB by default, which is 50 million cells of 4 Bytes. For larger dimensions we do not allocate a matrix, but use a single hash table with open addressing and linear probing (hash_storage_), keyed by the pair of keys packed into 64 bits. The table grows geometrically with the number of stored pairs, independently of the dimensions. The product of the dimensions must therefore fit into 64 bits; with keys of at most 32 bits it always does.

Template Parameters:

  • T – Type of the values stored in the map. Must be an unsigned type.

  • TrackInverted – Whether to track inverted indices for the first and second dimensions. To use this feature correctly, the mapping has to be reversible.

  • MaxMatrixBytes – Maximum size of the matrix in Bytes before switching to the hash table.

Public Types

using Cell = std::conditional_t<(sizeof(T) < sizeof(uint32_t)), T, uint32_t>

A matrix cell stores the value incremented by one; zero denotes a missing value.

using Row = std::unique_ptr<Cell[]>

A row is a dynamically sized array: its length is a runtime value, so ‘std::array’ does not apply, and ‘std::vector’ would add a second size and capacity per row.

#include <utils.hh>

A hasher for std::set, usable as the Hash template argument of unordered containers.

We deliberately do NOT specialize std::hash<std::set<A>> for arbitrary A: the standard only allows program-defined specializations of standard templates when at least one template argument is a program-defined type, so specializing it for e.g. std::set<unsigned> would be undefined behavior (and could silently collide with another library’s specialization for the same type).
