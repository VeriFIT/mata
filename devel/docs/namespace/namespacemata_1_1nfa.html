Explores reachable pairs (state_of_lhs, state_of_rhs) directly and stops at the first pair that is final in both automata. Nfa left_quotient(const Nfa &nfa, const Nfa &prefixes, Symbol first_epsilon = EPSILON)

Compute the left quotient of the language of nfa by the language of prefixes.

The left quotient (derivative by a language) is { w | there is u in L(prefixes) with u.w in L(nfa) }: the words of nfa with a prefix from prefixes removed. With prefixes accepting a single word u, this is the Brzozowski derivative of nfa by u.

The result is nfa with its initial states replaced by the states of nfa reachable by reading a word of prefixes. These are found by exploring the reachable pairs (state_of_prefixes, state_of_nfa) directly, without materializing the product, and pairs with a useless state of prefixes are never explored. The result is not trimmed: call Nfa::trim() to remove the states no longer reachable.

Symbols at or above first_epsilon move one side only, as in intersection(lhs, rhs, first_epsilon), so epsilon transitions of both automata are supported. The epsilon transitions of nfa are kept in the result.

Parameters:

  • nfa – [in] NFA whose language is quotiented.

  • prefixes – [in] NFA accepting the prefixes to remove.

  • first_epsilon – [in] Smallest symbol treated as a one-sided (epsilon) move.

Returns:

NFA for the left quotient of nfa by prefixes.

Nfa right_quotient(const Nfa &nfa, const Nfa &suffixes, Symbol first_epsilon = EPSILON)

Compute the right quotient of the language of nfa by the language of suffixes.

The right quotient is { u | there is w in L(suffixes) with u.w in L(nfa) }: the words of nfa with a suffix from suffixes removed.

The result is nfa with its final states replaced by the states of nfa from which nfa accepts a word of suffixes. These are found as in left_quotient(), but backward: pairs of a state of the reverted suffixes and a state of nfa are explored from the final states of both, moving nfa against its transitions over an index of predecessors, without reverting nfa or materializing the product. The result is not trimmed: call Nfa::trim() to remove the states that no longer reach a final state.

Symbols at or above first_epsilon move one side only, as in intersection(lhs, rhs, first_epsilon), so epsilon transitions of both automata are supported. The epsilon transitions of nfa are kept in the result.

Parameters:

  • suffixes – [in] NFA accepting the suffixes to remove.

  • first_epsilon – [in] Smallest symbol treated as a one-sided (epsilon) move.

Perform equivalence check of two NFAs: lhs and rhs.

The current implementation of Nfa does not accept input alphabet. For this reason, an alphabet has to be created from all transitions each time an operation on alphabet is called. When calling this function, the alphabet has to be computed first.

Nfa revert(const Nfa &aut)

Reverting the automaton by a counting sort (see Delta::reverted()): much faster than the three insertion-based variants below, which are kept for benchmarking.

Nfa fragile_revert(const Nfa &aut)

This revert algorithm is fragile, uses low level accesses to Nfa and static data structures, and is potentially dangerous when there are used symbols with large numbers (allocates an array indexed by symbols). It is asymptotically faster, however. For somewhat dense automata, the performance is the same or a little bit slower than simple_revert otherwise. Not affected by pre-reserving vectors.

Nfa simple_revert(const Nfa &aut)

Reverting the automaton by a simple algorithm, which does a lot of random access addition to Post and Move. Much affected by pre-reserving vectors.

Nfa somewhat_simple_revert(const Nfa &aut)

Reverting the automaton by a modification of the simple algorithm. It replaces random access addition to SymbolPost by push_back and sorting later, so far seems the slowest of all, except on dense automata, where it is almost as slow as simple_revert. Candidate for removal.

class Delta
#include <delta.hh>

Delta is a data structure for representing transition relation.

Transition is represented as a triple Transition(source state, symbol, target state). Move is the part (symbol, target state), specified for a single source state. Its underlying data structure is vector of StatePost classes. Each index to the vector corresponds to one source state, that is, a number for a certain state is an index to the vector of state posts. Transition relation (delta) in Mata stores a set of transitions in a four-level hierarchical structure: Delta, StatePost, SymbolPost, and a set of target states. A vector of ‘StatePost’s indexed by a source states on top, where the StatePost for a state ‘q’ (whose number is ‘q’ and it is the index to the vector of ‘StatePost’s) stores a set of ‘Move’s from the source state ‘q’. Namely, ‘StatePost’ has a vector of ‘SymbolPost’s, where each ‘SymbolPost’ stores a symbol ‘a’ and a vector of target states of ‘a’-moves from state ‘q’. ‘SymbolPost’s are ordered by the symbol, target states are ordered by the state number.

class DeltaBuilder
#include <delta.hh>

Append-only builder of a Delta whose transitions are produced in order.

Delta::add() is the right primitive for one unpredictable edit: it searches for the symbol and for the position of the target and shifts the vectors. An algorithm that already produces its output in order pays those searches for nothing. The builder promises the order instead, so every value is written at the end in constant time, and the finished posts are moved into the delta once.

The caller must keep these invariants; each is checked by MATA_ASSERT in Debug builds and assumed in Release builds:

  • begin_state() is called with strictly increasing source states;

  • begin_symbol() is called with strictly increasing symbols within one source state;

  • push_sorted_target() is called with strictly increasing targets within one symbol;

  • begin_symbol() / begin_state() are closed by finish_symbol() / finish_state() before the next one begins, and a symbol post with no target is not emitted;

  • no reference obtained from the builder survives finish_state().

Duplicate transitions are a precondition violation, not a silently collapsed input: use Delta::add(std::vector<Transition>&&) for data that may be unordered or contain duplicates.

Determinize automaton by the “Four Russians” subset construction.

This is the “Four Russians” technique of Arlazarov, Dinic, Kronrod and Faradzev (1970), applied lazily.

Gives the DFA of determinize_classical() up to the numbering of the states, usually much faster on large automata. The default algorithm of determinize(). The NFA states are cut into blocks, and the post of each combination of states of a block is computed once, when it first occurs, and kept in a table. The post of a macrostate is then a union over its blocks instead of its states.

With a reduction, it gives a smaller DFA for the same language, not always minimal. A reduction usually lowers the memory usage. Its effect on the time varies: inputs whose DFA shrinks a lot are much faster, others may be slower.

std::vector<State> identical_successor_classes(const Automaton &aut, size_t num_of_states, std::span<const Level> levels = {})

Classes of states that have the same finality, the same level, and, over every symbol, successors in the same classes.

Starts from the identity and merges states with identical successors, then states whose successors became identical by the merge, until nothing merges. Every merge joins classes with the same successors, so the partition stays a bisimulation and the quotient keeps the forward simulation of every state. It is far cheaper than the simulation itself: the first pass hashes each state post once, and after it only the classes of the predecessors of the states of an absorbed class are hashed again. inline uint64_t macrostate_signature(const StateSet &macrostate)

Signature of a macrostate: the OR of 1 << (q % 64) over its states q.

A superset can only have more bits set, so a bit present in macrostate_signature(a) and absent from macrostate_signature(b) exhibits a state of a that is missing from b and proves a ⊄ b. The converse does not hold: states that are congruent modulo 64 share a bit, so equal signatures prove nothing. The filter therefore only ever rejects, which is what the antichain subsumption tests need to stay sound.

Reduce NFA to an automaton with the minimum number of states using an external SAT solver.

Experimental. A counterexample-guided search: for k = 1, 2, …, a SAT solver looks for an automaton with k states consistent with a set of sample words, the candidate is checked for equivalence with nfa, and a distinguishing word is added to the samples until the candidate is equivalent or no k-state automaton exists. class ProcessedAntichain
#include <antichain-inclusion.hh>

The macrostates already processed for one state of the smaller automaton, bucketed by cardinality.

All entries stored here share the same state of the smaller automaton, so the dominance relation reduces to set inclusion between the macrostates of the bigger automaton. Cardinality alone then decides which entries can possibly be related to a candidate succ:

  • anti ⊆ succ requires |anti| ≤ |succ|, so the subsumption test reads nothing above |succ|;

  • succ ⊆ d requires |d| ≥ |succ|, so pruning reads nothing below |succ|;

  • at equal cardinality both reduce to equality, which is one comparison of two sorted vectors, and an entry equal to succ subsumes it, so pruning never has to consider that bucket. Inside a bucket the stored signature rejects most of the remaining pairs in O(1), before the node is read and the two sorted vectors are merged; see algorithms::macrostate_signature().

Only cardinalities that actually hold an entry get a bucket, kept in increasing order: the macrostates of one run occupy few distinct cardinalities out of the |bigger| possible ones, so indexing by cardinality would pay for (and scan) a bucket header per unused size.

Every node on the worklist is stored here as well, so marking the pruned nodes as dominated also removes them from the worklist, without scanning it.
