nfa::Nfa create_nfa(const std::string &pattern, const Re2Options &options)

Creates NFA from regular expression using RE2 parser.

At https://github.com/google/re2/wiki/Syntax, you can find the syntax of regular expressions with following futher limitations: 1) If you use UTF8 encoding, the created NFA will have the values of bytes instead of full symbols. For example, the character Ā whose Unicode code point is U+0100 and is represented in UTF8 as two bytes c4 80 will have two transitions, one with c4 followed with by 80, to encode it. 2) The created automaton represents the language of the regex and is not expected to be used in regex matching. Therefore, stuff like ^, $, , etc. are ignored in the regex. 3) Only the post-processing steps requested by options are run on the created automaton.

struct BodyToken
#include <parser.hh>

One token of a body line, with the flag telling whether the reader read it in quotes.

create_node() lets a quoted token be an operand even when it starts with & | or !, which the unquoted reader would take for an operator of the transition formula. The token is a view: parse_mf() points it into the name storage of its section, other code has to keep the bytes alive for as long as the token is used.

struct Re2Options
#include <re2parser.hh>

Options of the conversion of a regex to an NFA and of the post-processing of the result.

The defaults reproduce the behaviour of the overloads taking the individual parameters: epsilon transitions removed, the result trimmed and reduced by simulation reduction.

Public Members

bool keep_epsilon = {false}

Translate every instruction of the regex program to a state, with an epsilon transition for each step that consumes no symbol. Otherwise, the regex is converted directly to an NFA without epsilon transitions.

Symbol epsilon = {306}

Symbol representing epsilon transitions.

Encoding encoding = {Encoding::Latin1}

Encoding of the regex. Trim the created NFA. Without epsilon transitions, the conversion only creates states reachable from the initial state, and only a branch that can never match, such as ‘[^\x00-\xff]’ in Latin1, leaves useless states behind.

bool reduce = {true}

Reduce the created NFA by simulation reduction. The reduction costs seconds on regexes with a few thousand states, where the conversion itself takes milliseconds; turn it off for large regexes and when the result is determinized anyway.

class NewStates
#include <explicit-section-reader.hh>

The states the readers give to the names they meet first, given the names the caller mapped to states beforehand.

A mapped name gets its state allocated when used. A new name gets the lowest state that the automaton does not have yet and no mapped name has, so that it never shares the state of a mapped name, used later or not at all.

class ExplicitSectionReader
#include <explicit-section-reader.hh>

Reads the single section of a .mata input line by line, tokenizing every line as parse_mf() does.

The reader covers only lines that are lists of names, and in the formula mode also the operators and parentheses of transition formulas (&, |, !, (, )), which it splits off as tokens of their own, as parse_mf() does. It gives up on anything else parse_mf() would turn into an operator, on a second section, on a line continuation left open at the end of the input, and on every input parse_mf() rejects. Giving up is reported as Line::Unsupported, so that the caller can hand the input to the general reader, which then either reads it or reports the error.

class MataWriter
