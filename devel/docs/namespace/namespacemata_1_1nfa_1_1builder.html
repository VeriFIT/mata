Nfa create_random_nfa_tabakov_vardi(size_t num_of_states, size_t alphabet_size, double states_transitions_ratio_per_symbol, double final_state_density, const std::optional<unsigned int> &seed = std::nullopt)

Creates Tabakov-Vardi random NFA.

The implementation is based on the paper “Experimental Evaluation of Classical Automata Constructions” by Tabakov and Vardi.

Parameters:

  • num_of_states – Number of states in the automaton.

  • alphabet_size – Size of the alphabet.

  • states_transitions_ratio_per_symbol – Ratio between number of transitions and number of states for each symbol. The value must be in range [0, num_of_states]. A value of 1 means that there will be num_of_states transitions for each symbol. A value of num_of_states means that there will be a transition between every pair of states for each symbol.

  • final_state_density – Density of final states in the automaton. The value must be in range [0, 1]. The state 0 is always final. If the density is 1, every state will be final.

  • seed – Seed for the PRNG used. If no seed is given, the algorithm chooses one uniformly at random.

Nfa construct(const mata::parser::ParsedSection &parsec, Alphabet *alphabet, NameStateMap *state_map = nullptr)

Loads an automaton from a single parsed section of the mata format.

Unlike the IntermediateAut overload below, this one reads parsec verbatim: Initial and Final are taken as plain lists of state names and a body line is always a source symbol target triple. State names are therefore arbitrary strings, not subject to the q/a/n naming markers or to the Boolean formulas that IntermediateAut parses; symbol names are still resolved through alphabet, which decides which of them are valid. The two overloads consequently accept different inputs and cannot be merged: routing this one through IntermediateAut would subject the state names to the naming mode of the section (with the default States marked naming rejecting every name not starting with q) and would renumber states, as the IntermediateAut path collects names from an unordered set.

Parameters:

state_map – If not nullptr, the map from state names to states, which all overloads and readers fill in the same way. The names it maps beforehand keep their states, each allocated when the input uses its name; a final formula of an IntermediateAut that is true or negates states uses every name of the map it does not negate. Every other name gets the lowest state that the automaton does not have yet and that no name of the map had beforehand, so that it never shares the state of a mapped name, used later or not at all.

std::optional<Nfa> parse_explicit_from_mata(std::string_view nfa_in_mata, Alphabet *alphabet = nullptr, NameStateMap *state_map = nullptr, bool keep_quotes = false)

Reads an NFA from the .mata format in nfa_in_mata with the fast reader of explicit alphabets.

The reader skips the intermediate representations of the general reader (mata::parser::parse_mf() and IntermediateAut), and reads only the inputs whose transitions are source symbol target triples and whose Initial and Final lines list states. For those, it returns the NFA parse_from_mata() has always returned, except that the initial states are numbered in the order of the input.

Parameters:

  • nfa_in_mata – Input with a single @NFA or @NFA-explicit section.

  • alphabet – Alphabet translating the symbol names; nullptr reads them as numbers (IntAlphabet).

  • state_map – If not nullptr, receives the map from state names to states, see construct().

  • keep_quotes – Whether quoted names of body lines keep their quotes, see mata::parser::parse_mf().

Returns:

The NFA, or std::nullopt when nfa_in_mata needs the general reader, as do Boolean formulas, bitvector alphabets, enumerated namings, and malformed inputs. state_map is then left unchanged, while alphabet may have learned symbols of the lines read before.

Nfa create_from_regex(const std::string &regex, bool reduce = true)

Create NFA from regex.

The created NFA does not contain epsilons and is trimmed; with reduce, it is also reduced by simulation reduction. It uses the parser from RE2, see mata/parser/re2praser.hh for more details and options.

At https://github.com/google/re2/wiki/Syntax, you can find the syntax of regex with following further limitations: 1) The allowed characters are the first 256 characters of Unicode, i.e., Latin1 encoding (ASCII + 128 more characters). For the full Unicode, check mata/parser/re2praser.hh. 2) The created automaton represents the language of the regex and is not expected to be used in regex matching. Therefore, stuff like ^, $, , etc. are ignored in the regex. For example, the regular expressions a*b and ^a*b will both result in the same NFA accepting the language of multiple ‘a’s followed by one ‘b’. See also issue #494.

See also

mata::parser::create_nfa()

Parameters:

  • regex – regular expression

  • reduce – whether to reduce the NFA using simulation reduction; costly for large regexes

class BitvectorNfaReader
#include <builder.hh>

Reads NFAs with bitvector alphabets (@NFA-bits) over one shared set of minterms, as the general reader followed by Mintermization::mintermize() of all of them together does, but without the intermediate representations.

Transitions whose formulas are the usual Boolean combinations of symbols are read directly into BDDs. Any other @NFA-bits input goes through the general reader inside add(), so that all added automata still share one partition. The NFAs are the ones parse_from_mata() has always returned, except that the initial and the listed final states are numbered in the order of the input.
