Class mata::nfa::DeltaBuilder¶

class DeltaBuilder¶

Append-only builder of a Delta whose transitions are produced in order.

Delta::add() is the right primitive for one unpredictable edit: it searches for the symbol and for the position of the target and shifts the vectors. An algorithm that already produces its output in order pays those searches for nothing. The builder promises the order instead, so every value is written at the end in constant time, and the finished posts are moved into the delta once.

The caller must keep these invariants; each is checked by MATA_ASSERT in Debug builds and assumed in Release builds:

  • begin_state() is called with strictly increasing source states;

  • begin_symbol() is called with strictly increasing symbols within one source state;

  • push_sorted_target() is called with strictly increasing targets within one symbol;

  • begin_symbol() / begin_state() are closed by finish_symbol() / finish_state() before the next one begins, and a symbol post with no target is not emitted;

  • no reference obtained from the builder survives finish_state().

Duplicate transitions are a precondition violation, not a silently collapsed input: use Delta::add(std::vector<Transition>&&) for data that may be unordered or contain duplicates.

inline void begin_state(State source)¶

Starts the transitions of source. Every state before source keeps an empty post.

Reserves room for num_of_symbols symbols of the current source state.

inline void begin_symbol(const Symbol symbol)¶

Starts the targets of symbol under the current source state.

Appends target to the targets of the current symbol.

inline void finish_symbol()¶

Closes the current symbol. A symbol post without a target is dropped, since the delta stores no such post.

inline void finish_state()¶

Closes the current source state.

inline Delta finish()¶

Hands over the finished delta. The builder must not be used afterwards.
